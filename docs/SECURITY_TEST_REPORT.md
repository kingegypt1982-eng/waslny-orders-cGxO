# تقرير اختبار الأمان (Black-Box) — Waslny Orders API

> الهدف: `http://localhost:3000/api/v1` (تأكد أنه يعمل أولًا — لم يُشغَّل من هنا). كل الطلبات إلى `localhost` فقط: لا دفع حقيقي، ولا اتصال خارجي، ولا تعديل كود/إعدادات، ولا كتابة مباشرة على القاعدة. الحسابات أنشئت عبر endpoints التسجيل العامة فقط. لا أسرار في هذا التقرير (لا توكنات، لا كلمات مرور، لا مفاتيح، لا توقيعات).
> تاريخ التنفيذ: 2026-10-10. الحسابات والصفوف المنشأة مذكورة في الأسفل للحذف اليدوي.

## نتائج فاشلة أو مقلقة

**لا توجد نتائج فاشلة.** والنتيجة الحرجة الوحيدة المحتملة (اختبار 17) حُسمت لصالح الأمان: الحقن **مرفوض** صراحة برسائل `property … should not exist` (بفضل `forbidNonWhitelisted`)، وتأكد عبر SELECT أنه لم يُنشأ أي صف بقيم محقونة. ملاحظات غير حرجة:
- `50.999` قيمة صالحة فأنشأت شحنة PENDING حقيقية (وجلسة Sandbox شكلية دون دفع — لم يُفتح الرابط)؛ هذا سلوك صحيح لا ثغرة، لكنه يعني أن أي قيمة داخل الحدود تنشئ جلسة لدى Kashier.
- ` PATCH /orders/:id/status` القديم ما زال يقبل قفزات تتجاوز الإثبات حسب تقرير سابق — خارج نطاق هذه الجولة (يُعالج في مساره الخاص).
- لا معدل على مسار الـ webhook العام beyond العام (100/دقيقة) — مقبول حاليًا، ورُصد للمتابعة.
- وُجدت 3 شحنات SUCCEEDED قديمة (من اختبارات يدوية سابقة، ليست من هذه الجولة) — كل واحدة بمعاملة وحيدة صحيحة.

## ما لم يُختبر ولماذا

- **دفع حقيقي + webhook مُطلق من Kashier**: يتطلب متصفحًا لإدخال البطاقة في صفحة Kashier — غُطي جزئيًا سابقًا (جلسة حقيقية + webhook موقّع عبر tunnel مع fail-closed). أي TopUp ناجح مستقبلًا يجب أن يخضع لفحص test 24 دوريًا.
- **اختبارات التزامن الحقيقية** (سباق webhookين متوازيين فعليًا): غُطيت وحدةً بالـ mocks؛ الاختبار الشبكي المتزامن الحقيقي لم يُنفذ.
- **تطبيق الموبايل** و`e2e-spec` (يحتاج إقلاعًا كاملًا بقاعدة اختبار) — خارج النطاق المطلوب.
- فحص `50.999` أنشأ شحنة PENDING إضافية — مذكورة أدناه للحذف.
